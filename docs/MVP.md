# 12read MVP 方案

> 状态：已确认（Web/PWA · 本地优先 · EPUB 为主 + TXT 兜底 · 自用场景）
> 记录日期：2026 年

## 1. 目标

MVP 只用一句话定义成功标准：

> 把一本 EPUB 或 TXT 导入进来，能舒服地从第一页读到最后一页，关掉页面再打开还停在原处。

只服务这一个闭环。任何不增加「读得下去」概率的功能，都不进这一版。

### 已确认的边界

| 项 | 决定 |
| --- | --- |
| 平台形态 | Web / PWA，后续可套 Tauri 壳变桌面或移动应用 |
| 数据位置 | 本地优先（local-first）：书籍与阅读数据全部存在浏览器本地，无账号、无服务端 |
| 支持格式 | EPUB（主力） + TXT（兜底） |
| 目标场景 | 自用 / 小范围使用 |

## 2. 非目标（MVP 明确不做）

这些不是「以后再说」，而是「这一版做了一定会拖垮进度」：

- 账号体系、云同步、多端
- 书城、在线书源、网页抓取（版权 + 反爬 + 长期维护成本）
- PDF、漫画（重排与渲染是另一个产品）
- 社交、评论、分享、成就系统
- TTS 朗读（独立工程，后期是很好的加分项）
- 高级排版：竖排、脚注弹窗、多栏、用户自定义 CSS 注入

## 3. 功能范围

### P0 — 不做完就不算「能读书」

**3.1 导入与书架**

- 本地文件导入，支持拖拽与文件选择，可一次多本
- 书架列表/网格：封面、书名、作者、阅读进度、按最近阅读排序
- 删除、重命名（TXT 基本没有元数据，必须可改）
- 验收：导入 3 本书后刷新页面，书架内容与顺序不变

**3.2 解析管线**

- EPUB：解析 OPF 元数据、目录（NCX / nav.xhtml）、spine 章节 XHTML
- EPUB：保留原始 XHTML 结构，仅注入阅读样式，不重写排版
- TXT：编码自动识别（UTF-8 / UTF-16 / GBK，含 BOM）
- TXT：按「第X章」等正则切分章节，切不出来时按固定字数分段
- 验收：GBK 编码的中文 TXT 不乱码；损坏的 EPUB 给出错误提示而不是白屏

**3.3 阅读界面**

- 正文渲染 + 目录侧栏 + 上一章 / 下一章
- 排版设置：字号、行距、页边距（先只做这三项）
- 主题：白天 / 夜间（最多再加护眼黄）
- 翻页方式：**滚动或分页先只做一种**
- 验收：调整字号后正文立即重排，且当前位置不丢

**3.4 进度**

- 自动保存阅读位置，跨会话恢复
- 书架显示阅读百分比
- 验收：读到第 5 章关掉浏览器，重新打开直接落在第 5 章同一句话附近

**3.5 基础体验**

- 键盘/点击翻页、沉浸式全屏
- 空状态、加载状态、错误状态齐全

### P1 — 成本低、感知强，建议紧随其后

- 书签 + 划线笔记（纯本地）
- 书内搜索（先在当前章节内）
- 阅读统计（时长、天数）
- 数据导出/备份（JSON），避免用户数据被锁死
- PWA 离线可用

### 明确不做（见第 2 节）

## 4. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite + React + TypeScript | 反馈循环最短 |
| 状态 | Zustand（或轻量 Context） | 避免为 MVP 引入重型状态框架 |
| EPUB 解析 | JSZip + DOMParser 自研轻量解析 | 需要自己掌控存储结构与进度锚点 |
| TXT 编码 | BOM 优先，严格 UTF-8 解码失败则回退 GBK（浏览器原生 TextDecoder 支持 gbk） | 零依赖解决中文乱码 |
| 本地存储 | IndexedDB（idb 封装）：书籍二进制 + 元数据 + 进度 | 适合大对象与配额管理 |
| 样式 | CSS 变量驱动主题与排版 | 主题切换无需重渲染 |
| 分页 | CSS multi-column（第二阶段） | 先滚动跑通，再换分页 |
| 单元测试 | Vitest | 覆盖编码识别、章节切分、OPF 解析、进度锚点 |
| 端到端测试 | Playwright | 覆盖导入 → 阅读 → 进度恢复 |
| PWA | vite-plugin-pwa | 离线与安装能力 |

## 5. 数据模型

    Book {
      id, title, author, coverBlobId, format: 'epub' | 'txt',
      fileBlobId, size, chapterCount, encoding?, addedAt, lastOpenedAt
    }

    Chapter {
      bookId, index, title, href?, textLength, eof
    }

    Progress {
      bookId, chapterIndex, charOffset, percent, updatedAt, deviceId?
    }

    Annotation {
      id, bookId, chapterIndex, charOffset, length, text, note?, color, createdAt
    }

设计约束：

- 书籍正文以 Blob 存储，Chapter 只存索引与元信息，避免把整本书塞进内存
- Progress 从第一天就带 deviceId 字段，为将来同步预留，但 MVP 不实现同步

## 6. 关键设计决策（也是最容易踩的坑）

1. **进度必须用文本锚点，不能用页码。** 用户一改字号或窗口大小，页码就失效了。存「章节索引 + 字符偏移」，并预留「前文 30 字 + 后文 30 字」的引文锚点作为兜底。
2. **大章不能整块塞进 DOM。** 几 MB 的单章 HTML 直接渲染会卡死，需要分片或虚拟滚动。
3. **分页必须在 resize 时重算**，重算后要把锚点映射回新的页码。
4. **编码识别是刚需**，中文 TXT 的 GBK 问题几乎必然遇到。
5. **存储配额要有出口**：书籍体积大，配额写满时必须给用户明确提示与清理入口。
6. **数据可迁移**：导出/备份能力放到 P1，越早越好。

## 7. 里程碑与验收

| 阶段 | 内容 | 完成标志 |
| --- | --- | --- |
| M0 | 项目骨架：Vite + React + TS + Vitest + Playwright + lint | 空项目测试能跑通 |
| M1 | TXT 导入 → 书架 → 滚动阅读 → 进度保存 | 端到端可读完整本 TXT |
| M2 | EPUB 解析 + 目录跳转 | 端到端可读完整本 EPUB |
| M3 | 分页 + 排版设置 + 主题 | 字号/主题变化后位置不丢 |
| M4 | 书签 / 划线 + 章节内搜索 | 笔记可持久化并在重开后复原 |
| M5 | PWA 离线 + 导出备份 | 断网可读，数据可导出 |

每个阶段结束都必须按仓库 AGENTS.md 的要求补测试并提交 commit。

## 8. 风险

| 风险 | 应对 |
| --- | --- |
| EPUB 排版风格千奇百怪 | 只做结构解析与样式注入，不试图还原原书版式 |
| 分页 + 位置恢复的复杂度被低估 | 先滚动跑通闭环，分页作为 M3 独立阶段 |
| 范围蔓延到书源/同步 | 以第 2 节清单为准，新增功能必须写进本文档再开工 |

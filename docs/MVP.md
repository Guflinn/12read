# 12read MVP 方案

> 状态：已确认（Web/PWA · 本地优先 · **只做 TXT** · 自用场景）
> 更新时间：2026 年

## 0. 变更记录

| 日期 | 变更 |
| --- | --- |
| 2026 | 首版：Web/PWA + 本地优先 + EPUB 为主 + TXT 兜底 |
| 2026 | **调整为 TXT 优先、EPUB 移入 Backlog**；明确「段落可省、章节切分不可省」 |

## 1. 目标

MVP 只用一句话定义成功标准：

> 把一本 TXT 导入进来，能舒服地从第一页读到最后一页，关掉页面再打开还停在原处。

### 已确认的边界

| 项 | 决定 |
| --- | --- |
| 平台形态 | Web / PWA，后续可套 Tauri 壳变桌面或移动应用 |
| 数据位置 | 本地优先（local-first）：全部数据存浏览器本地，无账号、无服务端 |
| 支持格式 | **仅 TXT**（EPUB 延后，见第 11 节） |
| 目标场景 | 自用 / 小范围使用 |

## 2. 非目标（MVP 明确不做）

- 账号体系、云同步、多端
- 书城、在线书源、网页抓取
- **EPUB / PDF / MOBI 解析**（EPUB 延后，不是放弃）
- 社交、评论、分享、成就系统
- TTS 朗读
- 高级排版：竖排、脚注弹窗、多栏、自定义 CSS 注入

## 3. 段落与章节：先说清楚这两个概念

这是 TXT 阅读器的关键区分，直接决定 MVP 要不要做「目录」：

| 概念 | 在 TXT 中的形态 | 实现成本 | 结论 |
| --- | --- | --- | --- |
| 段落 | 换行符分隔的纯文本 | 几乎为零 | 不需解析：按换行切分，每段渲染为 p，CSS 处理首行缩进与段距 |
| 章节标题 | 独占一行的纯文本，如「第一章 穿越」 | 一个正则，约 10 行代码 | **必须做**，它是四件事的地基 |

章节切分不可省，因为它同时支撑：

1. **目录跳转** —— 5MB 的 TXT 约 250 万字，没有目录就无法「回到第 37 章」
2. **按章渲染** —— 性能命脉：不允许把百万字整块塞进 DOM，只渲染当前章
3. **可理解的进度** —— 「第 37 / 220 章」比「12.4%」对用户有用得多
4. **位置恢复** —— 章节索引 + 章内偏移，比全局字符偏移更稳定、更好调试

对比 EPUB 的目录解析（解压 ZIP → 解析 OPF → 读 spine → 解析 NCX/nav → 处理 XHTML 命名空间），TXT 的章节识别只是逐行跑正则，复杂度不在一个量级。

## 4. 功能范围

### P0 — 不做完就不算「能读书」

**4.1 导入与书架**

- 文件选择 + 拖拽导入，支持一次多本
- 书名从文件名推断（去掉扩展名），作者留空、可手动编辑
- 封面自动生成（纯色 + 书名首字），后续可替换
- 书架列表/网格：封面、书名、进度、按最近阅读排序；支持删除、重命名
- 验收：导入 3 本 TXT 后刷新页面，书架内容与顺序不变

**4.2 编码识别与解码**

- 顺序：BOM 判断 → 严格 UTF-8 解码 → 失败则回退 GBK
- 解码失败或疑似二进制文件时给明确提示，不白屏
- 验收：一份 GBK 编码的中文 TXT 导入后不乱码

**4.3 章节切分（核心）**

- 逐行正则识别标题行，覆盖常见形态：
    ^\s*第\s*[0-9零一二三四五六七八九十百千万两]+\s*[章节回卷部篇集]
    ^\s*(序章|楔子|序言|前言|引子|后记|尾声|终章|番外)
- 卷/部 行可作为分卷标记，MVP 先平铺为一级列表
- 兜底策略：识别不到章节时，按每 3000–5000 字分片，作为「分段」而非「章节」
- 每章记录：标题、起始字符偏移、字数
- 验收：一份典型网络小说 TXT 能切出正确章节数与标题

**4.4 阅读界面**

- 滚动流阅读（**先只做滚动，分页放到 M3**）
- 只渲染当前章，上一章/下一章切换
- 目录抽屉：章节列表 + 当前章高亮 + 点击跳转
- 排版设置：字号、行距、页边距
- 主题：白天 / 夜间
- 验收：切换章节时无卡顿；调整字号后正文立即重排且位置不丢

**4.5 进度**

- 保存「书籍 ID + 章节索引 + 章内字符偏移 + 总百分比」
- 跨会话恢复；书架显示百分比
- 验收：读到第 5 章关掉浏览器，重开直接落在第 5 章同一句话附近

**4.6 基础体验**

- 键盘翻页、点击翻页、沉浸式全屏
- 空状态、加载态、错误态齐全

### P1 — 成本低、感知强

- 书签 + 划线笔记（纯本地）
- 章节内文本搜索
- 阅读统计（时长、天数）
- 数据导出/备份（JSON）
- PWA 离线可用
- 章节手动修正（误切/漏切时允许合并、拆分、重命名）

## 5. 只做 TXT 可以省掉的

相对 EPUB 版本，以下工作整体消失：

- ZIP 解压、OPF/NCX/nav 解析、spine 读取
- XHTML 渲染与消毒、内嵌图片/字体/CSS 处理
- 封面提取（改为自动生成或手动设置）
- 元数据解析（改为文件名推断 + 手动编辑）
- 多级目录树（TXT 天然只有一级章节列表）
- CFI 等 EPUB 专有定位机制
- 「还原原书版式」这个几乎无解的难题

## 6. 不能省的

- **章节切分**（理由见第 3 节）
- **编码识别**（中文 TXT 的 GBK 问题几乎必然踩到）
- **进度锚点**（不能用页码，字号一变就失效）
- **大文件性能**（百万字不能整块进 DOM）

## 7. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite + React + TypeScript | 反馈循环最短 |
| 状态 | Zustand（或轻量 Context） | 不为 MVP 引入重型状态框架 |
| 编码 | BOM 优先，严格 UTF-8 解码失败则回退 GBK（浏览器原生 TextDecoder 支持 gbk） | 零依赖解决中文乱码 |
| 章节切分 | 自研逐行正则 | 逻辑简单、完全可控、易测试 |
| 本地存储 | IndexedDB（idb 封装） | 适合大文本对象与配额管理 |
| 样式 | CSS 变量驱动主题与排版 | 主题切换无需重渲染 |
| 分页 | CSS multi-column（M3 阶段） | 先滚动跑通，再换分页 |
| 单元测试 | Vitest | 覆盖编码识别、章节切分、进度锚点、文件名推断 |
| 端到端测试 | Playwright | 覆盖导入 → 阅读 → 进度恢复 |
| PWA | vite-plugin-pwa | 离线与安装能力 |

## 8. 数据模型

    Book {
      id, title, author?, format: 'txt',
      coverSeed, size, charCount, chapterCount,
      encoding, addedAt, lastOpenedAt
    }

    Chapter {
      bookId, index, title, startOffset, charLength
    }

    Progress {
      bookId, chapterIndex, charOffset, percent, updatedAt, deviceId?
    }

    Annotation {
      id, bookId, chapterIndex, charOffset, length, text, note?, color, createdAt
    }

设计约束：

- 正文以字符串/Blob 存储，Chapter 只存偏移与长度，**不重复存储正文**
- 保留 format 字段与 Book 抽象：将来接 EPUB 时无需重构数据层
- Progress 从第一天带 deviceId，为同步预留，MVP 不实现

## 9. 关键设计决策与坑

1. **进度用文本锚点，不用页码** —— 存章节索引 + 章内字符偏移，预留「前文 30 字 + 后文 30 字」引文锚点兜底
2. **只渲染当前章** —— 百万字整块进 DOM 必然卡死；跨章渲染要处理边界的「上一章末尾」
3. **章节切分要有兜底与容错** —— 正则失配时退回定长分片，绝不能因为没有章节就渲染不出来
4. **编码误判的处理** —— 用户应能在书籍详情里手动指定编码并重新解码（P1）
5. **存储配额** —— 大 TXT 累积很快，配额写满要有明确提示与清理入口
6. **数据可迁移** —— 导出/备份放 P1，越早越好
7. **文件名里的书名噪音** —— 常见「《书名》作者.txt」「书名(完结).txt」，需要清洗规则

## 10. 里程碑与验收

| 阶段 | 内容 | 完成标志 |
| --- | --- | --- |
| M0 | 项目骨架：Vite + React + TS + Vitest + Playwright + lint | 空项目测试能跑通 |
| M1 | TXT 导入 + 编码识别 + 章节切分 + IndexedDB 数据层 | 单测覆盖编码与切分的典型/边界用例 |
| M2 | 书架 + 章节渲染 + 目录抽屉 + 滚动阅读 + 进度保存 | 端到端读完整本 TXT 并恢复位置 |
| M3 | 排版设置 + 主题 + 键盘/全屏 + 分页模式 | 字号/主题变化后位置不丢 |
| M4 | 书签/划线 + 章节内搜索 + 手动修正章节 | 笔记与修正结果重开后复原 |
| M5 | PWA 离线 + 导出备份 | 断网可读，数据可导出 |

每个阶段结束都必须按仓库 AGENTS.md 的要求补测试并提交 commit。

## 11. Backlog：EPUB

EPUB 延后实现，但架构上预留：

- Book.format 与解析器接口保持可扩展（不同格式实现同一接口）
- 进度锚点设计对 EPUB 兼容（章节索引 + 章内偏移 可映射到 spine + CFI）

## 12. 风险

| 风险 | 应对 |
| --- | --- |
| 章节正则覆盖不全（各种冷门标题写法） | 兜底定长分片 + P1 提供手动修正 |
| 定长分片导致章节语义怪异 | 明确区分「章节」与「分段」，文案上不误导用户 |
| 超大文件解码时内存飙升 | 先按 Blob 读取，必要时在 Worker 中解码与切分 |
| 范围重新蔓延回 EPUB | 以第 11 节 Backlog 为准，需要时再单独立项 |

内测版大更新：0.1.2 之后攒下的 **10 项**一次性交付 —— 排版、翻页、换编码重解码、手动改分章、书签与划线、搜索、阅读统计、导出备份，外加一次大书性能专项。

### 新增

- **书架左下角版本号** —— 书架页左下角显示当前版本（如 `v0.1.3`），跟随主题、不挡点击，进阅读器自动隐藏。
- **正文字体与阅读宽度** —— 设置面板新增「字体」（宋体 / 雅黑 / 楷体 / 仿宋 / 等线）与「宽度」（窄 30rem / 中 40rem / 宽 52rem / 全宽）两行，和字号、行距一样重启后保持。
- **左右翻动翻页** —— 阅读器里 ← / → 变成翻上一页 / 下一页（每次一屏，留 40px 重叠），空格与 PageUp / PageDown 照旧；切章改用 **Ctrl + ← / →**（Mac 上 Cmd 也行）。起因是用户的 PageUp / PageDown 常被其他程序占用。
- **乱码书换编码重解** —— 编码认错、打开满屏乱码的书，在书卡上点「编码」重新挑自动检测 / UTF-8 / GBK / BIG5 / UTF-16 解一遍，不用重新导入（原始字节一直留在 `books/<bookId>/source.bin`）。重解码会清掉这本书的进度，弹窗里有提示。
- **手动改分章** —— 章节切分不准时不必重新导入：目录里每一节都能「改名」或「合并」（并进上一节）。正文一个字不动，只重写章节表；进度按编辑前的绝对字符位置重新落位，改完还停在刚才读到的地方。
- **书签与划线** —— 顶栏「🔖 书签」记一条（点下去会弹「已加书签」，修掉了之前静默无声、点了好几下不敢确定记上没有的问题）；选中正文点浮出的「划线」。目录抽屉分成「目录 / 书签 / 划线」三页，每条带章号与原文摘要，点一条跳回原处，也能就地删掉。数据库升到 schema v2，旧库自动迁移并先备份成 `library.db.bak-<版本>`。
- **章节内 + 全书搜索** —— 顶栏「🔍 搜索」或 Ctrl/Cmd + F 打开，边打字边搜（320ms 防抖），可在「本章」/「全书」间切换；命中列表带章号与前后各 24 字，点一条跳过去并闪一下。**故意不用 SQLite FTS5**（unicode61 对中文不切词、trigram 只支持 3 字以上查询，851 万字的书要建两千万级三元组），逐章扫正文是百毫秒级，零迁移、零索引体积。
- **阅读统计** —— 书架左下「阅读统计」按钮，给今天 / 累计 / 连续天数、最近 14 天柱状图与读得最多的 5 本书。只统计「窗口开着、人也没走开」的时间：每 15 秒记一段，窗口不可见或 60 秒没动静就停表；字数按同一章内前进的偏移差累加，跳章与回翻不算。
- **导出备份** —— 书架「导出备份」弹「另存为」，把整个书库打成一个 zip：SQLite 一致快照（`VACUUM INTO`）、每本书的原始文件，外加一份 `12read-backup.json` 清单。**只做导出，不做还原**；手写 ZIP，没有引入任何新依赖。

### 性能

- **大书专项** —— 拿一本 851 万字 / 41 节的书当靶子实测：导入 348ms、打开到首段 355–449ms、切章 52–60ms、滚完 58 万字的第一章 18 轮约 3.0s（最慢一轮 94ms）、主进程 heapUsed 38MB / rss 149MB、全书搜索 447ms、冷启动到书架 579–639ms，全在预算内。

### 修复

- **阅读统计面板排版重叠** —— 最近 14 天的柱状图下面，14 个「月-日」轴标签横排挤在 380px 宽的弹窗里（每柱只分到 20px，「09-28」要 ~30px），互相压成一团读不出是几号。现在把「月」「日」拆成上下两行（各 ~12px），并把柱子的画布（92px）与标签分成上下两块固定高度；三张指标卡也修正为等高等宽、说明统一贴底对齐。
- **长章节深处回到上次位置卡死** —— 在一章几十万字的书里读到深处，返回书架再打开只还原到前面一小截就再也不动（实测卡在 977 段 / 约 4 万字，等 20 秒也没反应）。原因是首屏只铺 2 万字，定位函数对超出已渲染范围的目标只能给到末尾，随之而来的滚动又把「上次位置」改写成这个被夹住的值，链子就断了。现在从进度 / 书签 / 搜索结果跳进长章节时，先把正文一次铺到目标之后一屏再滚动；实测回到章尾 6200 段只用 192ms。任何超过 5 万字的章节此前都会中招。

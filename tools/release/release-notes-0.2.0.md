内测版：这一版是**第二种书籍格式 —— EPUB**（.epub，含 EPUB 2 与 EPUB 3），另附**检查更新**功能。

### 新增

- **导入 EPUB** —— 拖进来或从对话框选，跟 TXT 一样用（顶栏按钮从「导入 TXT」改叫「**导入书籍**」）。**书名与作者取自文件本身**，不再只看文件名；书卡的角标从「编码」变成「EPUB」，卡片上的按钮相应从「编码」变成「提取」。
- **书架显示 EPUB 自带的封面** —— 能读到书里的封面图就用它（EPUB 3 的 `cover-image`、EPUB 2 的 `<meta name="cover">`，以及名字里带 cover 的图，三条线索依次找）；读不到（TXT 书、或书里没封面）继续用「渐变底 + 书名首字」的占位封面。老书点一下书卡上的「提取」即可补上。封面**完整显示不裁边**（比例不符时留边，衬底用中性的纸色，不再透出刺眼的渐变底 —— 对齐 iPhone 自带图书的做法）。
- **合集类 EPUB 三级目录（册 → 章 → 节）** —— 一个文件装十几本书的那种合集：目录里**每本书是一个一级分类**（可点，从这本书开头读起），书下面按「第几章」列，章下面再按「第几节」缩进列出（像 iPhone 自带图书那样细）。目录里不再有「1. 2. 3.」这种小序号。**普通书（目录本来就是平的）不受影响**，行为与以前完全一样。
- **封面图不再丢** —— 有些 EPUB 的封面是 `<svg><image xlink:href="封面.jpg"/></svg>` 这种写法，之前整张图会丢（实测一本合集：图片从 13 张变 31 张，第一张就是封面）。
- **按书自带的目录切章** —— 目录（EPUB 3 的 `nav.xhtml` 或 EPUB 2 的 `toc.ncx`）取**到第二层**并过滤「一 / 二 / 三」这类页码项，所以多卷本的「卷 + 章」都能正确成章；没有目录的书退回「一个文件一章」，超大章节再用 TXT 那套正则/分段兜底。
- **正文里的插图内联显示** —— 图片在正文里占一个占位符，渲染时原地换成图片（限宽居中）；图片由主进程按需提供，**不联网、不出书库**（只放行本书 `images/` 目录里的文件）。搜索命中的上下文里，占位符显示成「[图]」。
- **重新提取** —— 提取逻辑以后修好了，旧书不用重新导入：书卡上点「提取」即可拿原始文件重跑一遍（EPUB 没有「编码」这回事，所以不再让你选编码）。
- **整条链路与 TXT 零差别** —— 阅读、翻页、切章、目录、进度（关掉再打开回到原处）、书签与划线、搜索、阅读统计、导出备份，全部照旧工作；导出备份包里仍然是「数据库快照 + 每本书的原始文件」，插图属于派生物不进包。
- **调排版的面板改成开关** —— 顶栏 AA 点一下展开、再点一下收回；以前只能靠面板里的「完成」或 Esc 收回，误触之后再去找按钮很别扭。
- **只有标题的小页不再单独占一页** —— 真实书里章节标题常常单独占一页，以前要翻一张只有「第一章 红高粱」的空页才看到正文；现在它会并进后面的第一小节，标题落在正文开头。
- **短页面不再顶一句「本章完」** —— 封面页、册首页往往只有一两个字或一张图，以前打开就显示「本章完」，很突兀；现在这类页面不显示它。合集开头的封面页也从「开篇」改名叫「封面」。
- **检查更新（只提示不下载）** —— 书架左下角版本号旁边多了一个「检查更新」；进来书架时也会**自动静默查一次**（每次启动一次）。发现新版本时，左下角出现一颗「**有新版本 vX.Y.Z · 去下载**」的胶囊按钮，点一下用系统浏览器打开那个 Release 页面。**只提示、不下载、不安装** —— 更新包还是你手动下。检查失败一律**静默**，不弹错、不挡看书；手动点的时候才会给一句准话。

### 说明与取舍

- **不引依赖**：ZIP 解包、XML 解析、正文提取全是手写的（与 0.1.3 手写的 ZIP 写入器对称）。加密书（DRM）明确报「有版权保护，打不开」；损坏的书给中文提示而不是白屏。
- **排版仍以应用设置为准**：EPUB 自带的 CSS 与字体一律忽略（产品立场，不是偷懒）；粗体/斜体等行内样式只留文字。
- **暂不做的**：脚注弹窗、MathML、目录筛选；内嵌 SVG 当作一张图（内部文字会丢）。
- **性能实测**（真实中文书）：642KB / 90 章 **123ms**；8.29MB / 458 万字 / 328 章（切片落盘 + 31 张图）**466ms**。

### 数据与版本

- 数据库升到 **schema v5**（`chapter` 表纯加列 `group_title`，配合合集目录分组）：首次启动会自动迁移，迁移前照例先把库备份。
